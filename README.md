# Triple_combination_CFTRmodulators_genotype_levelAnnotation
This repository contains the R script implementing the Registry-based evidence-integrated framework described in the manuscript. The framework integrates real-world, clinical, and functional evidence sources to support CFTR variant-level and genotype-level therapeutic responsiveness classification.r.

## Repository structure and required files

The repository is organized into three main folders:

```text
.
├── R/
│   ├── main.R
│   └── registry_evidence_integration.R
│
├── data/
│   ├── ETI_real_world_data_exceptional_class_I_FCP
│   ├── ETI_real_world_data_FCP
│   ├── ETI_real_world_data_true_class_I_FCP
│   ├── ETI_responsive_variants_EMA
│   ├── VTD_responsive_variants_EMA
│   ├── Variants_individually_listed_as_responsive_to_ETI_FDA
│   ├── Variants_individually_listed_as_responsive_to_VTD_FDA
│   ├── 655_variants_tested_in vitro_with_ETI
│   └── 417_variants_tested_in vitro_with_VTI
│
└── test/
    ├── [example patient input file]
    └── [output template file]
```

- **`R/`** contains the R scripts implementing the framework:
  - `main.R`: main script to run the workflow.
  - `registry_evidence_integration.R`: source script implementing the Registry-based Evidence-integrated Framework.

- **`data/`** contains all supplementary and reference input files required for the evidence integration process.

- **`test/`** contains the example patient input file and the output template provided to test the workflow and demonstrate its application.

**`Notes`**

Exceptional Class I variants were identified as a specific evidence category within the framework. This classification based on the French compassionate programme for ETI was not considered evidence of VTD responsiveness. The ETI_real_world_data_true_class_I_FCP and ETI_real_world_data_exceptional_class_I_FCP files includes variant-level information from the French compassionate programme (FCP), including available in vivo clinical response data.

Patient input file
Users should prepare a patient input file containing their own CF data:
•	Patient ID
•	Allele 1 – Variant 1 (legacy name)
•	Allele 2 – Variant 2 (legacy name)
The patient file must contain the required variables in the same order and with the same column names as the example input file provided.
The file name can be changed according to the user's preference. However, if the file name is modified, the same name must be updated in the file list section of the Main.R script to allow correct file import.
Each row should correspond to one individual, identified by a unique patient ID, with the corresponding CFTR variant 1 and CFTR variant 2 information reported according to the required format.

Variant nomenclature and framework updateability
The script was developed using CFTR variant legacy names as the primary identifiers for variant matching and evidence integration. This choice reflects the European regulatory context of the framework, in which the European Medicines Agency (EMA) represents the primary reference for CFTR modulator indications. EMA-designated responsive variant lists are predominantly provided using legacy nomenclature.
HGVS nomenclature can be additionally provided for variant annotation and reporting purposes; however, the matching process within the current implementation relies on legacy names to ensure compatibility with regulatory evidence sources.
In some cases, regulatory variant lists include HGVS cDNA nomenclature rather than legacy names. These variants are maintained according to the nomenclature provided by the original evidence source to ensure accurate matching and evidence integration.
The framework is designed to remain adaptable over time. Updated regulatory classifications or new evidence sources can be incorporated by updating or replacing the corresponding input files while maintaining the same analytical pipeline.

Output files
After successful execution, two output files will be produced by the workflow in the same folder.
The first output file, “Patients_annotated_file”, is generated by the script and contains the original patient dataset with additional annotation variables resulting from the initial genotype-level assessment, including regulatory eligibility classification, including:
- pwCF carrying two true Class I variants;
- pwCF carrying at least one F508del variant;
- pwCF carrying at least one non-F508del CFTR variant designated as responsive by EMA for ETI and/or VTD.
The second output file, “Registry_based_evidence_integrated_framework_output”, is provided as a template file within the supplementary material and is populated by the script with the output of the Registry-based evidence-integrated framework, including the integrated real-world, clinical, and functional evidence supporting potential therapeutic responsiveness.
Notes
The predefined column names and column order of both output files must be maintained to ensure correct execution of the workflow.
